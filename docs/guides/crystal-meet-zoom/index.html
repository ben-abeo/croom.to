How-to guide

Connect Crystal Meet rooms to Zoom

Let each room join Zoom meetings through Zoom's Meeting SDK, including meetings hosted by customers and vendors, with no one signing in on the device.

This guide has two halves. The Zoom half is done once for all rooms by the person who administers your Zoom account: two apps in the App Marketplace, one review request, and one Zoom user per room, about 30 minutes at the keyboard. Zoom's review of the app then runs for a few weeks in the background; rooms join meetings on your own account in the meantime. The device half takes about five minutes per room. Rooms still join only when someone presses Join on the room page.

Before you begin

Access. The Zoom account owner, or an admin whose role has the Zoom for developers permission (then Develop shows at the top of the App Marketplace) and who may add users. The owner grants that permission at admin.zoom.us under User Management › Roles: edit the admin's role, then Role Settings › Advanced features › Zoom for developers, tick View and Edit.

Why four parts. Zoom lets an SDK app join meetings hosted by other Zoom accounts only once Zoom has reviewed the app, and, since March 2026, only as a signed-in Zoom user. The SDK app (step 1) joins your own meetings on its own; the review (step 2), the token app (step 3) and a Zoom user per room (step 4) let the room join everyone else's.

Secrets. You will collect a client id and secret (step 1) and an account id, client id and secret (step 3). Keep them out of email and chat; they go straight into a file on each device.

1

Create the Meeting SDK app

  • Sign in to the App Marketplace at marketplace.zoom.us with the account owner's login, or as an admin with the permission above. Open Develop at the top right and choose Build App. If there is no Develop menu, the permission is missing; see Before you begin.
  • Pick the type. In the dialog choose General App and press Create. Zoom folded its old "Meeting SDK app" type into the General App; there is no separate SDK type to look for.
  • Name it and make it account-owned. On Basic Information set the name to Crystal Meet rooms and choose Admin-managed where the page asks how the app is managed. It belongs to the account; nobody signs in to it.
  • Copy the development credentials. Still on Basic Information, App Credentials shows two pairs, Development and Production. Copy the Development Client ID and Client Secret; they go into the credentials file as sdk_client_id and sdk_client_secret. The development pair joins meetings on your own account straight away. The Production pair is for after step 2.
  • If the page insists on an OAuth Redirect URL before it lets you continue, enter https://crystalpm.com/. The rooms never use it; it only has to be a page on a domain you own.
  • Turn on the Meeting SDK. Open Features and its Embed tab (some layouts show Embed under Surface), switch Meeting SDK on and save. Leave the three switches beneath it off: programmatic join use case (the room joins when a person presses Join, as a Zoom user, so no exception is needed), Request Anonymous Join Exception (that is for apps that cannot use a ZAK; the rooms use one) and Use Device OAuth (the token app in step 3 does that job). The SDK downloads listed there are not needed: the room loads the web SDK itself.
  • Nothing else on the other pages. Access (secret token, event subscriptions, Plugin SDK), Surface (home URL, domain allow list, products, in-client features), Connect and Actions and Triggers all stay as they are; the room never shows anything inside the Zoom client. On Local Test, Add App Now is harmless either way.
  • Add the scope Zoom insists on. The build flow will not continue with an empty Scopes page. Press Add Scopes, search for zak and add user:read:zak:admin (View a user's ZAK). If it is not offered, search for token and add user:read:token:admin instead; if the list only has older names, pick User › View all user information, the one Zoom's own SDK guide names for admin-managed apps. In Scope Description write: "Fetches a conference-room user's ZAK so the room device can join meetings hosted by other Zoom accounts as that user." Add nothing else; every extra scope lengthens step 2.
  • Skip Local Test. The rooms do not sign in through the app, so it needs no event subscriptions and no "Add App Now" to work.

You should now see the app under Manage › Built Apps (Zoom also calls this list Created apps) with Meeting SDK on, and have its development client id and secret.

2

Submit the app to Zoom's review, unlisted

Needed only for meetings hosted by other Zoom accounts, which is most customer and vendor meetings. Zoom's rule: an SDK app may join meetings outside the account that created it only after Zoom has reviewed the app. Reviewed does not mean public; the app stays unlisted. Zoom asks developers to submit at least a month ahead, so do this the same day as step 1.

  • Fill in the listing. In the app's left menu open App Listing (older layouts: Information). Give a short and a long description, for example "Crystal PM's conference-room devices join Zoom meetings from the room's TV. Used only inside Crystal PM.", the company name, a category, the developer contact, and a support address and privacy policy page on crystalpm.com.
  • Verify the domain when asked. Every web address in the listing must be on a domain Zoom has verified for your account. Zoom shows the proof it wants, a DNS record or a small file on the site; whoever manages crystalpm.com's DNS can add it in minutes.
  • Tell the reviewers what it is. In the submission's test instructions say the app runs on a Raspberry Pi behind a conference-room TV, joins a meeting as an ordinary participant when a person presses Join, has no sign-in flow and no outside users, and is device-specific. Zoom accepts a short screen recording of a join, or a live session with the review team, for device-specific apps. Write "none" where it asks for test logins. Add a line of release notes. If the reviewers ask to see the app authorized, open Local Test and press Add App Now once as the admin; that is all the authorization it ever gets.
  • Keep it unlisted. Where the submission asks how the app is distributed choose Set my app as 'Unlisted', not Publish my app to the Zoom App Marketplace.
  • Accept the Marketplace Development Agreement and press Submit. Zoom's reviewers reply by email with questions or the approval; answer them quickly to keep the clock moving.
  • After the approval, copy the Production Client ID and Client Secret from App Credentials into each room's credentials file in place of the development pair (step 5) and restart the service. Zoom's reviewers approve the production pair; the development pair stays limited to your own account's meetings.

You should now see the app's status as In review, and later Approved. Until then rooms join meetings hosted on your own account only.

3

Create the Server-to-Server app for tokens

  • Build it. Develop › Build App, choose Server-to-Server OAuth and press Create; name it Crystal Meet room tokens.
  • Copy the credentials from App Credentials: Account ID, Client ID and Client Secret.
  • Fill in Information. Zoom will not activate the app without a short description, the company name and a developer contact name and email. Leave event subscriptions off on the Feature page.
  • Add two read-only scopes. Under Scopes › Add Scopes, search for zak and add user:read:zak:admin (View a user's ZAK), then search for token and add user:read:token:admin (View a user's token). Zoom's docs name the first for ZAKs and the second for the token request the room makes, so add both; nothing else is needed. The list only offers scopes the signed-in person's own role allows, so if either is missing, do this as the account owner.
  • Activate the app on the Activation page. Tokens only work while it is active.

You should now see the app listed as active, with the account id, client id and secret saved with the step 1 values.

4

Create a Zoom user for each room

  • Add the user. In admin.zoom.us go to User Management › Users › Add Users. Use a mailbox you can read, for example room1@crystalpm.com, and the Basic user type, which is free on a paid account.
  • Activate it. Open the invitation email in that mailbox and finish the sign-up.
  • Name it after the room. In the user's profile set the display name to the room's name, for example Room 1. That is the name hosts see when the room joins.
  • Repeat for Room 2 and Room 3.

You should now see one active Basic user per room, each named after its room.

Good to know

The room user never hosts anything and needs no licence. If you skip steps 2 to 4, rooms can still join meetings hosted on your own Zoom account; they just cannot join meetings hosted by other companies.

5

Put the credentials on each device

  • Make the file. Copy deploy/rooms/zoom-credentials.example.json to zoom-credentials.json and fill in the six values: the step 1 client id and secret (the development pair until step 2 is approved, the production pair after), the step 3 account id, client id and secret, and that room's user as room_user. Each room gets its own file because room_user differs.
  • Copy it to the device, for example scp zoom-credentials.json pi@crystal-meet-room-1.local:~/.
  • A device you are installing now. Add --zoom-credentials ~/zoom-credentials.json to the installer command from the setup guide.
  • A device that is already installed. Type sudo install -o pi -g pi -m 600 ~/zoom-credentials.json /etc/croom/zoom-credentials.json (your username instead of pi), then sudo systemctl restart croom.
  • Check it. Type /opt/croom/venv/bin/croom --check-zoom -c /etc/croom/config.yaml. It reads:
Zoom Meeting SDK: app AbC123xYz, signature minted (Zoom checks it only when a meeting is joined)
Zoom account: server-to-server token obtained for account 9XyZ12ab
Zoom room user: room1@crystalpm.com, ZAK obtained (valid 2 hours)
Ready: this room can join meetings on your own Zoom account now; meetings hosted by other accounts also need Zoom's approval of the SDK app, and the first outside-hosted meeting proves it.
  • Delete the copy in your home folder. Type rm ~/zoom-credentials.json.

You should now see the check end with "Ready".

6

Join a test meeting

  • Inside your account. Have a colleague start a Zoom meeting and paste its invitation link, passcode included, into the room page's Join with a link, or book it on the room's calendar and press Join now. Zoom's meeting appears on the TV within about fifteen seconds. This works from day one, with the development pair.
  • Outside your account, once step 2 is approved and the production pair is on the device. Join a meeting hosted by someone outside the company, or by a personal Zoom account. The room appears in the participant list under its own name, for example Room 1. If the host uses a waiting room, the room page says it is waiting until the host admits it. This step is the proof for the outside-host route, which has not yet been verified against a live meeting: if Zoom refuses with an authorization message even though the app is approved and the check passed, tell whoever set this up; the fallback is fetching the ZAK through the SDK app's own OAuth.
  • Controls. From the table page press Mute, Turn camera off, then Leave and Tap again to leave.

You should now see both meetings join, the room named after itself in the outside one, and the TV return to the room's idle screen after leaving.

If something is off

Troubleshooting

There is no Develop menu in the Marketplace

The signed-in admin's role lacks the Zoom for developers permission. The account owner adds it under User Management › Roles (Role Settings › Advanced features), or does steps 1 to 3 personally.

The check says "not configured"

It names the value that is missing or still a placeholder in /etc/croom/zoom-credentials.json. The four server-to-server values and room_user go together: fill in all of them or none.

The check says Zoom refused the credentials

The account id, client id or secret of the step 3 app is wrong, or the app is not activated. Copy them again from App Credentials and check the Activation page.

The check says no such user, or a scope is missing

The room_user must be an active user on this Zoom account. "Lacks a scope" quotes the scope Zoom wants; add that scope to the step 3 app under Scopes and activate it again.

The room page says the meeting is not authorized

The meeting is hosted by another account. Three things must all be true: the SDK app is approved (step 2), the device holds its production pair, and the file has the server-to-server values and room_user. Fix what is missing, restart the service and run the check. If all three are true and Zoom still refuses, the outside-host route needs the fallback described in step 6.

Wrong passcode or meeting not found

Paste the full invitation link with its passcode part. A bare meeting id cannot open a passcode-protected meeting. Zoom's exact reason shows on the room page.

The TV stays dark and the page says the SDK did not load

The device could not reach source.zoom.us. Check the device's internet access and any web filter, then try again.

Good to know

The room joins meetings as its own Zoom user through Zoom's supported Meeting SDK, so it is never mistaken for a bot. To take that away, deactivate the two apps or the room users in Zoom.
